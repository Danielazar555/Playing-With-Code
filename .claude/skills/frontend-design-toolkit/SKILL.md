# Frontend Design Toolkit (reference)

A meta-collection (community, wilwaldon/Claude-Code-Frontend-Design-Toolkit) of
what actually improves frontend output quality. Use alongside `frontend-design`
(aesthetic direction) and `ux-designer` (UX correctness). The recurring themes:

- **Commit to a visual tone before coding.** Name palette, type roles, and one
  signature element; reject anything that reads as a templated default.
- **Type is personality.** Don't ship the same neutral system-sans on every
  project; give the display role a deliberate face, scale, and tracking.
- **Motion with intent.** One orchestrated moment beats scattered effects;
  always respect `prefers-reduced-motion`.
- **Verify visually.** Screenshot the running UI at real device sizes and
  self-critique — "a picture is worth 1000 tokens" (pairs with `webapp-testing`).
- **Quality floor, always.** Responsive to mobile, visible keyboard focus,
  ≥44px targets, WCAG-AA contrast, semantic/operable controls.
